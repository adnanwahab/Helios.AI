# Connected feature workbench

Open /public/feature-workbench.html or use the homepage footer. This links all 15 feature categories to their existing experiences, exposes read-only connection checks, and adds an explicit browser-only notebook and account-scoped appearance settings. Status means advertised capability, not a verified successful write. Appearance is applied to the workbench only. Existing accounts are supported; public signup remains subject to existing Auth configuration. The 100-law simulation dashboard remains browser-local; use /research for shared rooms and future keyframes. GitHub proposal creation still uses the existing reviewed GitHub UI/inbox; this change does not add unattended GitHub writes. Email delivery and production database configuration require operator verification.

## Worker deployment

Use a separate Fly Machine or trusted operator terminal, not a Netlify request. The existing research worker API on the intended deployment must be enabled and a supervisor must create, plan and resume a room. Only run on a room whose participants have authorized sending shared research inputs to the model provider. No private journals. Set server-side HELIOS_RESEARCH_ORIGIN (trusted HTTPS site), HELIOS_RESEARCH_ROOM (one explicitly selected room), HELIOS_RESEARCH_WORKER_TOKEN (same as that deployment), OPENAI_API_KEY, HELIOS_WORKER_AI_ENABLED=1, HELIOS_WORKER_CONCURRENCY (1–20), HELIOS_WORKER_MAX_TASKS (1–1000; default 10), and optionally HELIOS_WORKER_MODEL. Run node scripts/research-worker.mjs. The runner exits when its task budget is exhausted, no tasks can be claimed, or a lane fails. It does not poll indefinitely, discover rooms, or restart itself. Model output is preliminary analysis without external browsing, never a verified source or a real vote. Worker outputs enter needs_review through the existing fenced lease API. Configure a separate staging room and test with a low budget before production. No worker process, secrets, or paid provider call is started by this PR. Existing Fly storage and preview isolation are unchanged.

## Validation

Run bun test and bun run build; use /public/feature-workbench.html locally. Test preferences with two independent verified sessions for the same account and a different account; verify stale revisions reject and journal notes never appear in API requests. For deployed preview, account persistence may remain disabled by design. Inspect actual Netlify and Fly health responses and use an isolated database for write tests. Never create test votes in production.
