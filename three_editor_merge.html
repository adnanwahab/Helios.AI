    Layout

    
  
    Rules
    
  
      
    
    1. The number is the path. Write a journal's number as 10 digits: the first 5 name the chapter folder, the next 3 the page file, and the last 2 the line in that page, counting from 0. Journal 4,123,456,789 is line 89 of l00/pages/41234/567. Constitutions follow the same rule with their node number.
      2. 
    
    2. Scrolling is arithmetic, never LIST. Pair r holds journals 2r and 2r+1, both on page floor(r ÷ 50). The client reads CURRENT.json once, a chapter head once per 100,000 journals, then one page per 50 pairs, fetching the next page before the reader reaches it. LIST returns at most 1,000 keys per call, so it stays out of the browse path.
      3. 
    
    3. Pages never change; heads do. Rewriting a page writes the next generation (g0003, then g0004) under a new key, so the CDN can cache pages for a year. Each chapter's head lists the current generation of its 1,000 pages and is cached for 60 seconds.
      4. 
    
    4. Edits land in delta/, then compact. An edit is a small PUT under delta/. A compactor folds a chapter's deltas into new page generations written with If-None-Match: *, then replaces the head with If-Match on its ETag, so two compactors can't overwrite each other.
      5. 
    
    5. Constitutions form a binary tree. Node i at level k merges nodes 2i and 2i+1 of level k−1, so level 33 is one constitution for everyone. Editing journal n makes one node per level stale, node floor(n ÷ 2k), 33 in all. This page merges level 1 live; model-written constitutions would be read from l01/ and up the same way as journals.
      6. 
    
    6. Number journals by place. If numbers follow a Hilbert or S2 cell order of where writers live, every subtree is a place: level 10 is about 1,000 neighbors, level 20 about a million people.
      7. 
    
    7. Spread writes across chapters. S3 handles at least 3,500 writes or 5,500 reads per second per partitioned prefix, with no limit on the number of prefixes. Backfill with one writer per range of chapter folders; readers come through the CDN.
      8. 
    
    8. Jump by id. ids/ maps a journal id to its number: the first 6 hex characters of the id pick one of 16,777,216 files of about 480 entries each.
      9. 
  
    
  
    Page format
    
  
    One JSON object per line, 100 lines, gzipped and served with Content-Encoding: gzip so the browser unpacks it.
    
  
    {"n":4123456789,"id":"8f3c2a91…","updated":"2026-11-21","text":"Need: …"}
