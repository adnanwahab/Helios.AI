Put your fork online in three steps

GitHub turns off Actions on new forks, so your copy won't publish a website until you switch it on. It takes about two minutes.

  1. Turn on Actions

    In your fork, open the Actions tab and click enable workflows.

  2. Choose GitHub Pages

    Open Settings → Pages. Under Source, pick GitHub Actions.

  3. Deploy

    In Actions, run Deploy static preview to GitHub Pages, or just push a commit to main.

Your site appears at https://YOUR-USERNAME.github.io/Helios.AI/ and updates every time you push to main.

Or run it on your computer

You'll need Bun and Node 22 or newer.

Terminal
# replace YOUR-USERNAME with your GitHub name
git clone https://github.com/YOUR-USERNAME/Helios.AI.git
cd Helios.AI
bun install
bun run dev
# then open http://localhost:3000

Locally, the 100 goals, proposals and amendment history are saved in a small database on your machine. See docs/backend.md to connect Supabase and deploy the full app.

What your fork includes

The free GitHub Pages site is a static preview. The full app needs a server.

Works on GitHub Pages

  • All the Helios landing pages and tabs
  • 100 Shared Goals and Helios Unified
  • The Dynamicland science lab
  • Notes kept in each visitor's own browser

Needs the full app (server)

  • Email sign-up
  • Saving proposals and amendments for everyone
  • The YC Research proxy tab

Your fork never sends visitors' data to the original Helios. You run your own copy.
